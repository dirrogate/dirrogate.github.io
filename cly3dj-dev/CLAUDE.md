## What this is
A two-deck vinyl DJ setup for passthrough XR, inspired by Vinyl Reality Lite (EntroPi Games, Quest 3, v0.6.0).
We are building our own app. We are NOT modding the Vinyl Reality Lite APK.

## DO NOT BREAK: record groove rendering (owner-approved 26 Sep, see #57)
- (#137, 28 Sep) The grooves are now a 1024 x 1 ring strip read by radius in the shader (recordMaterial), not a 2048 disc canvas; 1024 texels over REC.R = the old canvas's pixel density, one texel per step. The rules below still hold; where they say pixel ring / canvas, read strip texel.
The grooves in VR now match the owner's Vinyl Reality reference. Any change to records must keep all of this:
- `textures.js drawRecordSide`: every ring is `g.arc(C, C, r * px, ...)` (radius in PIXELS). The first build used `r` in metres, which drew tiny circles under the label and made the grooves invisible for days. Same for the roughness map: `(REC.OUT - k / rpx) * rpx`.
- One 1-pixel ring per step from REC.OUT to REC.IN; its lightness comes from the track's 8192-bin loudness envelope (audio.js decode), averaged over the bins that ring covers, normalised by the 3rd/99.5th percentiles, `L = 5 + 30 * e^0.8`, hue 225, sat 6%. Quiet passages = dark bands, loud = lighter bands, breakdowns show as gaps. That is the waveform the owner wants.
- NO synthetic concentric rings, ridges or fixed-pitch lines. NO groove normal map (`normalMap: null` on records and the crate disc). The owner rejected both.
- Gloss is set only through the material (specularIntensity / envMapIntensity / roughness map base), never by adding rings, clearcoat or anisotropy streaks. Current (#93): blank sides roughness 0 in the groove area (100% smooth); cut sides roughness ~0.05 (0.03 quiet .. 0.07 loud), i.e. 95% of the blank side's gloss; label 0.67; specularIntensity 0.15 on both. envMapIntensity has no effect (scene.environment overrides it).
- Before shipping any record change: headless render a record top-down and check the bands follow the envelope and the grooves span lead-in to run-out.

## Decisions so far
1. Stem separation: dropped entirely.
2. Sync: one-shot "meet in the middle". DJ sets both pitch faders roughly by hand, presses SYNC on the mixer (optional controller hotkey on Quest). Both decks move to the average effective tempo; both pitch faders animate to their exact positions over a few hundred ms; the follower's phase is aligned with a short temporary rate nudge (about one beat), never a hard playhead jump. No persistent lock afterwards.
3. Target devices: Meta Quest 3 now; Meta VR Glasses (ships spring 2027, controllers optional); Snap Specs (WebXR in the Snap OS browser, gamepads not usable). So: WebXR, hand input first, controller buttons as a bonus.
4. Look: match Vinyl Reality Lite's visual language (direct-drive deck, 2-channel scratch mixer, flight-case crate with track screen) using procedural Three.js geometry and PBR materials. No Technics / SL-1200 wordmarks, no Vinyl Reality branding. Record labels generated from track title + BPM.
5. Keep models behind an interface so a purchased GLB can replace a procedural part later (tonearm is the likely candidate).
6. Hosting: WebXR runs inside a published claude.ai artifact (26 Sep). Test early that the artifact frame grants xr-spatial-tracking on Quest Browser; GitHub Pages stays as fallback.
7. Sync range: +-16 (units to confirm: BPM or %). Pitch fader range to match.
8. Phase lead: the deck whose pitch fader was touched last, before SYNC or during the sync glide. That deck keeps its phase; the other nudges.
9. Pseudo stems via a PAN knob per channel (not real stem separation): full left = acapella, centre = full track, full right = instrumental. The knob selects content only and never pans spatially; the result goes to both L and R of master/headphones. Chain: deck > stem knob > trim > EQ > filter > fader.
10. Pseudo stem method (proposed): on track load, a worker runs STFT centre-channel extraction over the decoded buffer and stores one mono "centre/vocal" buffer. Instrumental = original minus vocal, computed live, so centre position sums back to the untouched original. Worklet reads all from the same playhead, so scratching and pitch still work with zero added latency.
11. Start screen: choose Full VR (immersive-vr) or Passthrough (immersive-ar), buttons shown only if supported; desktop preview otherwise.
12. (26 Sep) Pitch fader range is +-16% (answers decision 7 / open question on units). Sync accepts any meet point inside +-16%.
13. (26 Sep) SUPERSEDES 9 and 10: no pseudo-stem extraction. Owner pre-prepares some MP3s with vocal on L and instrumental on R. Per-channel PAN works like a hifi balance knob: centre = both, hard left = L only, hard right = R only. Result is folded to both output channels (proposed: fold only for split-flagged tracks; normal stereo tracks get a regular pan).
14. (26 Sep) Grooves: rendered procedurally in a shader, not as geometry. One spiral per side from lead-in to run-out; ring brightness and spacing driven by the track's own loudness envelope mapped to radius (loud = wider pitch, quiet/breakdowns = visible bands), anisotropic sheen, filtered to avoid moire. Needle radius follows playhead on the same mapping.
15. (26 Sep) Records have an A and B side, one MP3 per side. Pairing by filename: `name_a.mp3` + `name_b.mp3` = one record (suffix case-insensitive, base name must match). A file with no partner = single-sided record with a blank B side. Flipping in hand swaps which file the platter loads.

External mics/line sources go in over USB-C (USB audio class device), with Settings > Advanced > External Microphone enabled and a restart (Antlion setup guide). A phone's headphone out is ~0.5-1 V vs mic-level ~10 mV: needs a ~30 dB attenuator (with DC block, the mic pin carries bias) into a USB-C TRRS dongle (mono), or a class-compliant USB line-in interface (stereo). Unverified on Quest Browser: whether enumerateDevices lists internal and USB inputs separately.
- 27 Sep (turntable physics research, owner's KAB 'Study of Cogging Torque in Technics SL-1200 Turntables' PDF + specs): MK2 motor = 3-phase brushless DC with iron stator, 16-pole ring magnet, 12 slots; torque set by a DC control voltage; bi-directional (can pull back = electronic brake, 45->33 change near instant). Speed control = quartz PLL on a frequency-generator coil round the magnet: 50.55 Hz at 33 1/3 (= 91 pulses/rev, one pulse = 3.96 deg = 19.8 ms of audio), speed+phase signals through an integrator and ~300 ms RC filter; response to a load change ~300 ms (1/6 rev) on MK2, ~1 s on the pre-1979 original. Spec: 0% speed change for load torque up to 0.8 lb-in (~0.09 N m), i.e. integral action, zero steady-state error below that. Starting torque 1.5 kg cm (0.147 N m), build-up 0.7 s, platter 2.0 kg with rubber mat (MK7: 0.18 N m, 0.7 s, 1.8 kg incl. slipmat, coreless = no cogging, 4 torque/brake levels). Measured with a gram gauge: bearing friction alone 1.5 g at the platter edge (6 in) ~0.0022 N m; bearing + cogging 3.5 g at the edge; cogging alone ~2 g at the edge (~0.003 N m peak), 48 cogging steps/rev (26.64 Hz at 33 1/3), rumble -56 dB = inaudible. Hand-turned slowly and released, an MK2 platter comes to a near stop and rocks back slightly (detent). Author's summary: low running torque motors, easily stopped by hand at normal speed. Implication: bearing friction alone would coast ~40+ s from 33 1/3, so the current 7 s power-off coast (#48) needs a real measurement before changing.
